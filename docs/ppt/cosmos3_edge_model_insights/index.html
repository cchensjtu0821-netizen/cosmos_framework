3

具身关键创新

Cosmos 3 论文主张 × LingBot-VA 对照

A

理解与动作共骨干

Reasoner 的离散 AR 路径与 video/action 的连续 diffusion 路径，在统一 MoT 中联合注意；指令理解、世界预测、动作生成不再是三套模型。

B

统一动作语义 + 域适配

FD / ID / joint policy 三种动作模式共享表示；domain-aware 输入/输出投影适配不同 embodiment 的动作长度与语义。

C

Edge 是“缩小后的全能力”

4B 双塔 MoT 保留语言—视觉—动作联合建模；相对 Nano 16B 更接近边缘部署预算，而不是另造一套轻量 Policy 架构。

Cosmos3-Edge 更强项更小参数规模；原生物理推理 + 多动作模式；共享骨干、域专属 I/O。
LingBot-VA 更强项因果 AR rollout、KV-cache 长时记忆、推理与机器人执行异步并行。
口径：Edge 当前 32-action RoboLab 链路；VAE decode 默认关闭；网络输出采用 PyTorch runtime [33,64]。 Sources：Cosmos 3 TR / NVIDIA model card · LingBot-VA paper & official repo · local profiling docs
本页从左到右讲三件事。第一，Edge Policy 的单次请求不是一次网络 forward，而是先做输入构造和 VAE 编码，再进入四步 UniPC；默认 guidance=3，因此每步分别执行 conditional 与 unconditional 两次网络前向，总计八次。第二，参数量不能直接代表时延：Edge、Nano 与 LingBot-VA 的 token 布局、采样器和闭环机制不同，所以表格刻意展示真实计算结构，不给出误导性的统一 FLOPs。第三，Cosmos 的具身价值不只是“模态更多”，而是让理解、世界预测和动作生成共享 MoT，并通过 domain-aware 投影处理不同 embodiment。竞争判断要保持克制：Cosmos Edge 在统一性和参数规模上更占优，LingBot-VA 在因果闭环、KV cache 和异步执行上更成熟。 资料来源：NVIDIA Cosmos 3 Technical Report（arXiv:2606.02800v4）、NVIDIA Cosmos3-Edge-Policy-DROID model card、LingBot-VA: Causal World Modeling for Robot Control（arXiv:2601.21998v2）、Robbyant/lingbot-va 官方仓库，以及仓库内 ROBOLAB_POLICY_EDGE_NANO_IO_SHAPES.md 与 ROBOlab_POLICY_INFERENCE_PROFILING.md。
