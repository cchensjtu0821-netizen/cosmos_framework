# Agent Work Log — 2026-08-03

## ONNX numerical-equivalence rewrites

Status: `RESOLVED`

- The causal mask rewrite no longer uses the rejected `Clip + Add` approach.
  It gathers only unmasked scores and uses `ScatterND` overwrite semantics on
  an all-`-Inf` base, preventing masked NaN/Inf values from contaminating the
  result.
- Vision rank lowering now preserves the `[p, q, C]` patch-element order with
  `SpaceToDepth` and the inverse `DepthToSpace(mode=DCR)` pipeline.
- The compatibility rewrite reaches finite, numerically equivalent outputs
  with both passes enabled, subject to the standard server-side regression
  checks for future graph changes.

Affected code: `scripts/rewrite_action_policy_onnx.py`.

## ScatterND compatibility during OMC conversion

Status: `RESOLVED`

- OMG does not accept the intermediate `ScatterND(reduction=add)` produced by
  the earlier `ScatterElements` lowering.
- For validated static contiguous axis-0 row updates, finalization lowers it
  to `Slice(data) -> Add(updates) -> Concat(prefix, updated, suffix)`.
- Unsupported or unresolved ScatterND reductions cause finalization to fail
  rather than silently changing graph semantics.

Affected code: `onnxsrc/finalize_onnx.py`.

## OMG conversion appears to stop during model parsing

Status: `INVESTIGATING`

- The process was not hung; it completed a long constant-folding phase and
  then failed IR shape inference.
- The terminal error is at `node_ScatterND_239` (`ScatterNdUpdate`): OMG sees
  `indices.dim[0]=20` but `updates.dim[0]=19`, rejects the node, and exits with
  `Failed to generator IR graph`.
- Earlier Reduce identity-check messages and optional plugin load warnings are
  not the terminal failure.
- Next action: inspect this node's three ONNX inputs, attributes, static and
  inferred shapes, constant indices, producer, and consumer context in the
  exact finalized model supplied to OMG. Then derive and validate an exact
  Slice-based overwrite lowering for this pattern.

Inspection result:

- ONNX metadata for `node_ScatterND_239` is internally valid: data is
  `[64,3201,1]`, indices are `[20,1]`, and updates are `[20,3201,1]`.
- Updates come from a transpose of a fixed strided Slice. OMG logs that Slice
  as `start=1, end=60, step=3, dim=64`, which has 20 elements under ONNX's
  exclusive-end ceil semantics, but later reports the updates dimension as 19.
- The leading diagnosis is an OMG strided-Slice shape-inference discrepancy,
  surfaced at the downstream ScatterND verifier rather than an invalid ONNX
  ScatterND shape.
- Planned workaround: eliminate the overwrite ScatterND with a validated
  static sorted-unique-index `Slice`/`Concat` construction, avoiding reliance
  on OMG's ScatterND verifier.
- The resolved indices are exactly 20 sorted unique rows
  `[1,4,7,...,55,58]`, with constant stride 3 and bounds inside the 64-row
  data tensor. This confirms the node is eligible for an exact overwrite
  lowering: preserve untouched data row ranges and interleave one-row Slices
  from the 20-row updates tensor, then concatenate in row order.
- `onnxsrc/finalize_onnx.py` now applies that lowering generically to every
  default-overwrite ScatterND with static sorted unique `[N,1]` row indices
  and an exactly matching update shape. Concat fan-in is capped at 64 through
  a hierarchy when necessary.
- Every remaining ScatterND is included in the finalize report with its name,
  reduction, inputs, and known input shapes. Full-coordinate causal ScatterND
  layouts are not forced through the row-wise rewrite; their OMG compatibility
  must be established by the next server conversion.

Validation remains server-side because the local workspace does not contain
the private OMG/OMC or ONNX/CUDA runtime.
