## Edge Policy component-size clarification

Status: `RESOLVED`

- Action postprocessing has no learned model or parameters; the action input/
  output heads are part of the denoiser.
- The Wan2.2 VAE architecture contains about 704.7M parameters in its full
  encoder/decoder module (about 149.6M on the encode path). Its released BF16
  weights occupy about 1.41 GB; the full FP32 checkpoint is about 2.82 GB.
- The released Edge transformer is 6.75 GB in BF16 including token embedding
  and language-model head. A fixed denoiser graph with prompt embeddings
  externalized and no language-model head is approximately 2.84B parameters:
  about 5.68 GB BF16, 11.35 GB FP32, or a 2.84 GB raw INT8 weight floor.
- Exact ONNX/OMC artifact size must be measured as the model file plus its
  external-data sidecar; graph metadata, quantization scales, alignment, and
  compiler packaging add overhead to the raw weight floor.

Status: `RESOLVED`

- `prepare_data_total` encloses sequence-plan construction, video/device
  normalization, VAE encode and output cast, conditional/unconditional text
  tokenization, initial packing, vision/action noise creation, conditioning
  blends, and flattened condition-buffer concatenation.
- The full 33-frame uint8 video is currently moved and converted to CUDA FP32
  before the causal-VAE prefix selection. For the recorded 544x736 layout this
  is about 39.6 MB of source data and 158.5 MB of FP32 output traffic outside

- Architecture-invariant noise is generated with NumPy on CPU and copied to
  the target device. Full-sized `initial_noise`, `condition_reference`, and

  not CUDA-kernel self time; parent-minus-VAE cannot be attributed solely to

### Durable technical clarifications

- `Input & Batch Prep` shows the collapsed preprocessing outputs. Video is
  `[1,3,33,544,736]`; the strict batched action shape is `[1,33,64]`, while
  `[33,64]` is the per-sample shape consumed by packing. Prompt is still text
  until tokenization produces conditional `105 -> 107` and unconditional
  `17 -> 19` token layouts.
- The service receives one current RGB observation (or one stitched multiview
  canvas), writes it to pixel frame 0, and leaves frames 1--32 as zero future
  placeholders. Action row 0 is current state and rows 1--32 are future-action
  placeholders.
- In the standard single-view causal-VAE inference path, prefix encoding sends
  only the first real pixel frame through the VAE. It constructs the full
  nine-frame latent with zero tail positions, then the conditioning blend keeps
  latent frame 0 and replaces latent frames 1--8 with diffusion noise. A full
  33-frame VAE encode remains a fallback for unsupported layouts such as
  multi-item/multiview or non-causal tokenizers.
- The raw VAE latent `[1,48,9,34,46]` comes from the padded pixel bucket
  `[1,3,33,544,736]`. `_remove_padding_from_latent` uses the original
  `540x640` image size and spatial factor 16 to crop it to
  `[1,48,9,33,40]`; this is padding removal, not a second VAE compression.
- The 3,060 vision tokens are latent patches, not ViT outputs. The VFM pads
  latent height `33 -> 34`, applies a `2x2` spatial reshape at each of nine
  latent times, and obtains `9*17*20=3060` vectors of width
  `48*2*2=192`; `vae2llm` is a linear `192 -> 2048` projection before MoT.
- Sampler condition and uncondition branches share one current joint
  video/action latent. Each step evaluates both branches on the same latent and
  timestep, merges their velocities with CFG, updates that single latent with
  UniPC, and feeds the result to both branches on the next step. The slide now
  returns the sampler loop to a shared junction that fans out to both branches.

### Paper-backed embodied innovations

- Cosmos 3 treats an action token as the causal transition between adjacent
  world states and maps heterogeneous embodiments into shared geometric action
  components: ego pose, effector pose, and grasp state. Relative SE(3) motion
  and domain-aware input/output projections preserve embodiment-specific action
  interfaces while sharing the MoT backbone.
- One sequence model supports forward dynamics (clean action -> noisy future
  video), inverse dynamics (clean visual transition -> noisy action), and policy
  mode (jointly noisy action and future video). The PushT ablation reports a
  72% relative ID-MSE reduction and policy coverage `74.1% -> 77.3%` for joint
  FD/ID/policy training, with a modest FD-PSNR tradeoff.

## Domain-aware action projector visibility

Status: `OPEN`

- Edge Policy does execute two domain-aware action projections on every VFM
  network call. `action2llm` selects domain-specific weights using the packed
  per-token `domain_id` and maps action tokens from `64 -> 2048` before MoT;
  `llm2action` selects the corresponding domain-specific output weights and
  maps noisy action hidden states from `2048 -> 64` after MoT.
- These are `DomainAwareLinear` layers, not a separate transformer stage. The
  current profiler includes `action2llm` inside `encode_action` and
  `llm2action` inside `action_head`, so the Edge report's `4.813 ms` and
  `0.786 ms` are inclusive eight-call totals rather than isolated projector
  timings. Their theoretical request-level work is included in
  `encode_action=0.000145 TFLOPs` and `action_head=0.000069 TFLOPs`.
- The current architecture slide hides this inside generic action packing and
  generation labels. A future revision should expose
  `Domain Projector-In (action2llm)` before the MoT packed hidden sequence and
  `Domain Projector-Out (llm2action)` before action velocity/postprocessing;
  the performance table should label `encode_action` and `action_head` as
  inclusive of those projectors.

## Flat joint sampler-state clarification

Status: `RESOLVED`

- The slide's `flat [572352]` is not transformer token packing or another
  learned projection. It is the per-sample UniPC state vector created by
  reshaping the continuous vision noise (`48*9*33*40 = 570240`) and action
  noise (`33*64 = 2112`) and concatenating them to `572352` scalars.
- Clean `condition_reference` values and their `condition_mask` are flattened
  in exactly the same vision-then-action order. This lets one sampler update a
  synchronized joint video/action state while restoring conditioned positions
  after each step.
- Each denoise call splits the vector back into vision/action tensors, runs the
  VFM branches, and concatenates the resulting vision/action velocities back
  into the same flat layout for the next UniPC update. Text and domain IDs are
  conditions/metadata and are not part of the sampled vector.
- The slide label is technically correct but ambiguous; a clearer audience
  label would be `Joint UniPC state [572352]` rather than merely `flat`.
