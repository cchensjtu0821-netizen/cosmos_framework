## Remove Pow from exported RMSNorm

Status: `INVESTIGATING`

- The deployment backend must not receive ONNX Pow. Tensor squares in the
  RMSNorm implementations used by the three unified MoT variants, plus the
  standalone Cosmos3 Edge reasoner, now use `hidden_states * hidden_states`
  instead of `hidden_states.pow(2)`.
- Static Python configuration powers such as `patch_size**2` are intentionally
  unchanged: they compute host-side integers and do not create ONNX Pow nodes.
  Non-square powers are not mathematically replaceable by a single Mul.
- Pow is now part of the strict Policy ONNX target-operator audit. A fresh raw
  export is required for the source change; Step 5 must fail if any Pow remains
  from another graph path. Numerical and OMG/OMC validation remain server-side.
- A subsequent OMG result isolated a more direct Pow source: Edge uses the
  Nemotron `relu2` activation between `mlp.up_proj` and `mlp.down_proj`, and
  its `.square()` implementation exports Pow. The upstream projection passed
  while the following down projection failed compatibility checking. `relu2`
  now computes one ReLU followed by self-Mul, and explicitly overrides any
  same-named Transformers activation so behavior is independent of whether
  that library version already registers `relu2`.
- The first override incorrectly registered a tensor function. Transformers
  4.57 uses a lazy class-instantiating `ACT2FN`, so lookup called that function
  without a tensor and model construction failed. The override is now an
  `nn.Module` class, matching the registry contract; this supersedes commit
  `515aab8` before any ONNX was exported.
