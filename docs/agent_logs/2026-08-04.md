  the remaining eight. The same shape explains all 784 hierarchical Concats.

## OMG Mul broadcast failure after ScatterND lowering

Status: `INVESTIGATING`

- The latest finalized model progresses beyond the previous
  `node_ScatterND_239` failure, so the overwrite ScatterND lowering removed
  that terminal blocker.
- OMG now fails shape inference at `node_mul_23`: one inferred dimension is
  `124` where the backend expects `128`. The preceding `GatherND_*` nodes are
  successfully constant-folded into `StridedSliceV2` and are not themselves
  the terminal error.
- The logged dynamic-quant scale length is `3093`, equal to `3201 - 108`; this
  correlates the failure with the causal branch split at sequence position
  108, but does not identify the mismatched Mul inputs or axis conclusively.
- Next action: inspect `node_mul_23` and its immediate producers/consumers in
  the exact finalized ONNX supplied to OMG, including ONNX metadata shapes,
  inferred shapes, initializers, and quant-parameter mapping. Do not rewrite
  the Mul until the two broadcast operands are identified.
- An earlier operand report of `[3093,1,128]` and `[3093,16,128]` is
  superseded by the complete OMG log. During constant folding,
  `GatherND_288`, `_295`, `_306`, and `_313` are lowered to slices whose
  second interval is explicitly `0:124` on a dimension of size 124; their
  associated `Unsqueeze` outputs feed the RoPE region before `node_mul_23`.
  OMG then rejects broadcasting that 124-wide value against a 128-wide input.
- This is concrete evidence of a real 124-wide intermediate in OMG's folded
  graph, not merely a generic broadcast diagnostic. It still does not prove
  whether the finalized ONNX already contains that width or OMG introduced it
  while folding. Do not apply the previously considered blanket `Expand`:
  expansion cannot make 124 values semantically equivalent to 128 values.
- The dynamic-quant scale length `3093` exactly matches the sequence slice
  `108:3201`; it does not by itself explain the feature-width mismatch. Next
  action: inspect the exact finalized ONNX and report both inputs and producer
  chains for `node_mul_23`, plus the data shapes and constant-index bounds of
  those four GatherND nodes before finalization. Compare the same names in
  `quant_params_v2` only after establishing the ONNX-side dimensions.
- `onnxsrc/finalize_onnx.py` now materializes an exact static Mul broadcast as
  `Expand -> Mul` only when both operand shapes are fully known, have equal
  rank, and differ on exactly one axis from singleton 1 to the target size.
  The reported `[3093,1,128] * [3093,16,128]` pattern therefore becomes an
  explicit `[3093,16,128]` input without padding or inventing feature values.
  The finalize report records every affected Mul and shape. If the exact graph
  instead exposes a real 124-wide operand, the pass deliberately does nothing
  and server inspection remains required.
- The supplied v4 OMG log confirms this is v4's terminal failure. Earlier
  overwrite-ScatterND `ConcatD` nodes, including a logged zero-length concat
  input, report `const_folding_success` and are not the exit point. Nodes still
  named `node_GatherND_288`, `_295`, `_306`, and `_313` are logged as
  `StridedSliceV2` because finalization preserved their names while replacing
  their op types; this is consistent with v4's `GatherND=0` count.
- All four folded RoPE slices use feature interval `0:124` on a size-124
  dimension. OMG then reaches `node_mul_23`, reports that dimension 124 must be
  128, fails `MathBroadCastInfer`, and aborts IR generation. This establishes
  the immediate cause, but not whether width 124 already exists in v4 ONNX,
  came from quant/shape metadata, or was introduced by OMG inference. Exact
  v4 producer-chain inspection remains required before changing semantics.
